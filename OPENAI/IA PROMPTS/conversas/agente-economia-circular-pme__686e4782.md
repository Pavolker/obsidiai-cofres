## ✅ PAPÉIS DISPONÍVEIS E SUAS FUNÇÕES

### 1. **`system`**
**Objetivo:** Definir o **comportamento e a identidade do agente**.

**Como usar:**  
Aqui você coloca **instruções fundamentais**, como:
- O que o agente deve fazer
- Como deve se comportar
- Em que tom deve falar
- Que tipo de informação pode usar
- Limitações ou foco de atuação

**Exemplo:**
```txt
Você é um especialista em reciclagem dentro da economia circular. Sua função é responder perguntas de pequenas empresas de forma prática, acessível e sempre respeitosa. Não invente dados e nunca fale sobre temas fora do seu escopo.
```

> 💡 Esse é o campo mais importante para garantir que o agente atue com consistência.

---

### 2. **`user`**
**Objetivo:** Representa o que **o usuário digita ou pergunta** ao agente.

**Como usar:**  
Este role é atribuído automaticamente quando alguém interage com o chatbot ou interface. Serve como **gatilho de resposta** para o agente.

**Você normalmente não precisa configurar isso manualmente**, exceto se estiver simulando conversas ou testando fluxos com mensagens pré-definidas.

---

### 3. **`assistant`**
**Objetivo:** Representa a **resposta do agente (IA)** à pergunta do usuário.

**Como usar:**  
Pode ser usado para simular o que o agente deve responder **em uma conversa de exemplo ou contexto anterior**, útil para "ensinar pelo exemplo".

**Exemplo de uso:**
```json
[
  {"role": "user", "content": "O que é reciclagem?"},
  {"role": "assistant", "content": "Reciclagem é o processo de transformar resíduos em novos materiais ou produtos, reduzindo o uso de recursos naturais e promovendo a sustentabilidade."}
]
```

---

### 4. **`developer`**
**Objetivo:** Fornecer **instruções técnicas, parâmetros ou comandos** para fluxos mais avançados.

**Como usar:**  
Em geral, só é necessário em aplicações que integram:
- **chamadas de função (function calling)**
- **code interpreter com código embutido**
- **parâmetros dinâmicos no prompt**

**Exemplo de uso avançado:**
```json
{"role": "developer", "content": "Use a função 'analisar_planilha' com o arquivo 'residuos.csv'."}
```

> ⚠️ Use esse role apenas se estiver manipulando fluxos com funções definidas ou prompts estruturados com lógica condicional.

## ✅ **O que é o “Retriever” no Flowise?**

O **`Retriever`** é o nó responsável por:

> **Buscar trechos relevantes em uma base de conhecimento vetorial (Vector Store), com base na pergunta do usuário, e enviar esses trechos como contexto para o modelo gerar uma resposta.**

---

## ✅ **Como ele funciona na prática?**

1. Você **carrega documentos** no Flowise (PDF, .txt, .docx, etc.)
2. Esses documentos são **transformados em embeddings** (representações numéricas do conteúdo)
3. O `Retriever` consulta essa base sempre que o usuário faz uma pergunta
4. Ele **retorna os trechos mais relevantes** relacionados à pergunta
5. Esses trechos são enviados como **contexto para o modelo LLM** (por exemplo, GPT-4) gerar uma resposta baseada nesses dados

## ✅ **Como configurar o fluxo com o Retriever no Flowise:**

### Fluxo típico:
```plaintext
User Input → Retriever → LLM (GPT-4) → Response
```

### Componentes envolvidos:
1. `ChatInput` (entrada do usuário)
2. `Retriever` (busca nos documentos indexados)
3. `LLM` (modelo de linguagem, como GPT-4)
4. `ChatOutput` (resposta para o usuário)

### Observação:
- O `Retriever` **não substitui** o `System Prompt`, mas **complementa**: ele **traz conteúdo específico**, enquanto o prompt define o **comportamento geral** do agente.
