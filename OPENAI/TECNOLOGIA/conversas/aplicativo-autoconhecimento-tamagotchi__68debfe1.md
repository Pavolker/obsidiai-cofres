## ⚙️ Mecânica do Jogo
1. **Criação do Eu-Virtual**
   - O usuário escolhe um avatar simbólico (semente, cristal, chama, animal, etc.), representando seu **estado inicial de consciência**.
   - Esse avatar evolui à medida que o autoconhecimento é “alimentado”.

2. **Alimentação com Ações**
   - Cada “refeição” equivale a uma **prática de autoconhecimento** vinculada a um objeto.  
     Ex.: escrever um breve diário → “Capacidade de autoanálise” (objeto 9);  
     registrar o humor do dia → “Emoções que você expressa” (objeto 11);  
     ligar para alguém importante → “Laços que te sustentam” (objeto 6).

3. **Ciclos de Cuidado**
   - O app sugere **três momentos diários** (manhã, tarde e noite) em que o usuário deve registrar algo.
   - Esses registros funcionam como “alimento”, e a ausência deles causa **desgaste do avatar** (sinais de desequilíbrio).

4. **Equilíbrio dos Foyers**
   - As ações estão ligadas a um **Foyer**:
     - Interne (interioridade)
     - Externe (relações e cultura)
     - Stratégique (decisão e equilíbrio)【10†TESE PATRICIA.pdf】  
   - O avatar mostra visualmente se o usuário está alimentando de forma equilibrada ou não (um triângulo dinâmico de energia).

5. **Eventos Aleatórios (Sinais Fracos)**
   - De tempos em tempos, surgem “eventos surpresa” (ex.: um dilema, um questionamento, uma frase inspiradora), pedindo ao usuário uma resposta rápida.  
   - Isso simula a **vida real** e treina a atenção ao inesperado (deriva natural).

# PROMPT MESTRE — “App Lucidez” (HTML+CSS+JS)

## 0) Objetivo
Crie um aplicativo web minimalista (“App Lucidez”) em **HTML + CSS + JS puro** (sem frameworks) que:
- Apresente **uma pergunta por vez** sobre um dos **27 Objetos de Autoconhecimento**.
- Ofereça **apenas 5 opções** (níveis de lucidez) para o usuário escolher.
- Registre a resposta, atualize indicadores e exiba um **Mapa de Lucidez** (triângulo: Interne, Externe, Stratégique).
- **Sem textos longos**, sem feeds, sem perfis públicos, **sem gamificação externa**.
- **Arquitetura modular** com **camada de abstração de dispositivo** para que implementações específicas (ex.: notificações, vibração, armazenamento) possam variar por plataforma **sem impactar** o núcleo.

## 1) Princípios
- **Minimalismo de interface e código**: poucos elementos, poucas dependências, sem libs externas.
- **Imutabilidade de contratos**: módulos se comunicam por **interfaces estáveis** (ports & adapters).
- **Isolamento**: UI, domínio, persistência e device adapters **separados**.
- **Privacidade local**: dados só em `localStorage` (por padrão). Sem back-end.
- **Acessível** (WCAG AA): navegação por teclado, ARIA, contraste mínimo 4.5:1.
- **Responsivo**: mobile-first; depois tablet/desktop.

## 2) Arquitetura (Ports & Adapters)
- **/core/** (domínio): lógica de objetos, cálculo de lucidez, regras de negócio.
- **/ui/** (apresentação): HTML + CSS + JS da tela (pergunta + 5 opções + feedback + mapa).
- **/infra/** (adapters): armazenamento, relógio, notificações, vibração, haptics, etc.
- **/platform/** (device adapters):
  - **web/** (navegador padrão)
  - **ios/** (WKWebView – haptics via bridge; se não disponível, no-op)
  - **android/** (WebView – vibração/notification via bridge; se não disponível, no-op)
- **/config/**: flags, i18n (pt-BR default), objetos.json.

Cada adapter implementa a **mesma interface**. O **compositor** escolhe o adapter com base no `navigator.userAgent` e `feature detection` (sempre fallback seguro).

## 3) Estrutura de Pastas
```
/app
  /core
    domain.js            // regras: 27 objetos, foyers, escala 1..5, cálculos
    scoring.js           // índices por objeto, foyer e total
    scheduler.js         // lógica “questão do dia” (manhã/tarde/noite)
  /ui
    index.html           // página única
    styles.css           // BEM/utilitário simples; variables CSS
    view.js              // controladores da tela (pergunta, 5 botões, feedback)
    chart.js             // desenho do triângulo (SVG puro)
  /infra
    storage.port.js      // interface StoragePort {get, set, list, clear}
    time.port.js         // interface TimePort {now, todayBuckets}
    notify.port.js       // interface NotifyPort {schedule, cancel, requestPermission}
    haptics.port.js      // interface HapticsPort {light, medium, heavy}
  /platform
    /web
      storage.adapter.js // localStorage
      time.adapter.js
      notify.adapter.js  // Notifications API + fallback no-op
      haptics.adapter.js // navigator.vibrate + no-op fallback
    /ios
      storage.adapter.js // bridge iOS ou localStorage fallback
      ...
    /android
      storage.adapter.js // bridge Android ou localStorage fallback
      ...
  /config
    flags.js             // feature flags (ex.: enableNotifications)
    i18n.js              // pt-BR strings curtas
    objetos.json         // 27 objetos + mapeamento de foyer
  /tests
    core.spec.js         // testes unitários do domínio (sem DOM)
    adapters.spec.js
  /build
    vite.config.js (opcional) ou script de bundle simples
```

## 4) Domínio (Regras)
- **Escala fixa (5 níveis)**:
  1 = Não percebo; 2 = Raramente; 3 = Às vezes; 4 = Frequentemente; 5 = Clara/Consistente.
- **27 Objetos** (carregar de `config/objetos.json`), cada um mapeado a **Foyer**:
  - **Interne** (interioridade/reflexividade)
  - **Externe** (relações/culturalidade)
  - **Stratégique** (processualidade/decisão/regulação)
- **Cálculo**:
  - Índice por objeto = média ponderada das respostas (últimos 30 dias; se <3 respostas, usar média simples).
  - Índice por foyer = média dos seus objetos.
  - **Mapa**: triângulo SVG com vértices correspondendo aos 3 foyers; normalizar para [0..1].
- **Questão do Dia**:
  - 3 slots: manhã, tarde, noite (configuráveis).
  - Seleção pseudo-aleatória garantindo **cobertura equilibrada** dos 27 objetos ao longo da semana.

## 5) Fluxos da UI
**Tela Única** (index.html):
1. **Header minimalista**: “Lucidez • hoje”
2. **Pergunta** (texto curto do objeto atual).
3. **Cinco botões** (1..5) — grandes, com rótulos curtos + aria-label.
4. **Feedback imediato**:
   - Flash de luz (CSS) + `HapticsPort.light()`.
   - Mensagem curta: “Registro salvo”.
5. **Mapa de Lucidez** (SVG triângulo) — atualização suave (requestAnimationFrame).
6. **Histórico compacto**: micro-sparkline por objeto (opcional, escondido por padrão).
7. **Footer**: “Dados só no seu dispositivo.”

Sem navegação complexa. Sem múltiplas páginas.

## 6) Persistência
- `StoragePort`: chave `lucidez:v1:{date}:{objectId}` → {value: 1..5, ts}.
- `lucidez:v1:settings` → preferências (notificações, horários).
- Migração simples por `version` se schema mudar.

## 7) Compartimentação por Dispositivo (crítico)
- **NUNCA** importar APIs de dispositivo diretamente do `ui/` ou `core/`.
- Toda funcionalidade dependente de device (notificações, haptics, storage além de localStorage) **passa pela porta** em `/infra/*.port.js`.
- Cada plataforma fornece seu **adapter** em `/platform/{web|ios|android}/*.adapter.js`.
- Um **resolver** escolhe o adapter disponível; se nada, **no-op** estável.
- Trocar/adicionar plataforma **não altera** `core/` nem `ui/`.

## 8) Acessibilidade
- Botões 44px+; foco visível; navegação por Tab/Enter/Espaço.
- `role="radiogroup"` nos 5 níveis; `aria-checked` atualizado.
- Contraste AA; rótulos curtos e descritivos.

## 9) Performance
- JS < 40KB minificado (meta).
- Zero imagens bitmap; **SVG inline**.
- CSS crítico no `<head>`, restante inline no `index.html` (sem bloqueio).
- Debounce de render no mapa.

## 10) Segurança/Privacidade
- Sem analytics por padrão.
- Sem rede; sem cookies.
- Botão **“Apagar tudo”** (confirmação dupla).

## 11) Configurabilidade (flags)
- `enableNotifications`: default `false`.
- `questionSlots`: `["08:00","13:00","20:00"]`.
- `historyWindowDays`: `30`.

## 12) Testes
- **Core** testado com casos:
  - cálculo por objeto/foyer
  - distribuição de “questão do dia”
  - normalização do triângulo
- **Adapters**: mocks para web/ios/android; garantir **no-op** seguro.

## 13) Entregáveis
- Repositório com a estrutura acima.
- `index.html` funcional (SPA minimalista).
- `objetos.json` preenchido com os 27 objetos + foyer (pt-BR).
- Testes rodando via `npm test` (ou script vanilla).
- `README.md` com instruções de build e deploy (Netlify/GitHub Pages).
- **Sem dependências** obrigatórias (opcional: um bundler leve).

## 14) Critérios de Aceitação
- Ao abrir o app, exibe **uma** pergunta com 5 opções; ao clicar, salva o registro e atualiza o **Mapa de Lucidez**.
- **Triângulo** reflete, em tempo real, a média dos 3 foyers.
- **Sem erros** quando APIs de notificação/haptics não existirem (no-op).
- Emular iOS/Android/Web substituindo apenas `/platform/*` (o núcleo não muda).
- Recarregar a página mantém histórico (localStorage).
- Acessibilidade: navegação completa por teclado + aria ok.
